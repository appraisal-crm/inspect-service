# inspect-service

On-site inspection service for the Appraisal CRM. It creates an inspection when a
request is scheduled, lets the assigned inspector record property data and photos,
and emits `inspect.completed` when the visit is done.

Part of a multi-repo system — see `request-service` for the reference layout and
conventions, and `CLAUDE.md` for the full charter.

## Responsibilities

- **Consume** `request.status_changed` (topic `request.events`): a request entering
  `inspection_scheduled` creates an inspection (status `scheduled`, unassigned).
- **Serve** the inspector-facing API: view assignments, fill property data/notes,
  register photos, complete the inspection.
- **Produce** `inspect.completed` (topic `inspect.events`) through a transactional
  outbox so request-service can advance the request and notification-service can
  notify the client.

## Design

- **DB `inspect_db`** — `inspections` (one per request, `request_id` UNIQUE),
  `inspection_photos` (S3 object keys), `inspection_statuses` lookup, `outbox`.
- **Inspection state machine:** `scheduled → completed` only. Completion is the
  single event-producing transition, guarded by a CAS on `status = 'scheduled'`.
- **Photos** live in S3 (Yandex Cloud); only the object key is stored. Uploads use a
  presigned URL — `internal/storage` is a stub until the S3 SDK is wired.
- **Idempotency** — the consumer dedups by `event_id` in Redis (`SET NX EX`); a
  redelivered creation is also absorbed by the `request_id` UNIQUE constraint.
- **Auth** — Keycloak JWT (JWKS). Inspectors are limited to inspections assigned to
  them; appraiser/admin see all. Assigning an inspector is appraiser/admin only.

## HTTP API

| Method | Path                          | Roles                       | Description                                  |
|--------|-------------------------------|-----------------------------|----------------------------------------------|
| GET    | `/health`                     | public                      | Health check                                 |
| GET    | `/inspections`                | inspector, appraiser, admin | List (inspector: own; appraiser/admin: all)  |
| GET    | `/inspections/{id}`           | inspector, appraiser, admin | Get one                                      |
| PATCH  | `/inspections/{id}`           | inspector, appraiser, admin | Set notes/property_data; assign inspector    |
| POST   | `/inspections/{id}/photos`    | inspector                   | Register a photo, get a presigned upload URL |
| POST   | `/inspections/{id}/complete`  | inspector                   | Complete → emits `inspect.completed`         |

Swagger UI at `/swagger/` (docs generated by `make generate`).

## Local development

```bash
# 1. Shared bus + auth (Kafka/Keycloak), once, from the repo root
docker compose -f ../infra/docker-compose.yml up -d

# 2. This service's data infra (Postgres :5435 + Redis :6382)
docker compose up -d

# 3. Migrate + run
cp .env.example .env
make migrate-up
make run
```

Or run everything (infra + migrations + service) in containers:

```bash
docker compose --profile app up -d --build   # needs ../infra up for Kafka/Keycloak
```
